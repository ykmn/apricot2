# «Скачать всё»: экспорт-диалог с режимами «отдельно» / «склеить»

Дата: 2026-08-20
Статус: одобрено, готово к написанию implementation-плана

## Проблема

Кнопка «Скачать всё» в панели «Выбранные фрагменты» сейчас работает без
диалога: она сразу экспортирует каждый фрагмент лог-листа отдельным файлом
(`app.js:955 exportAll()`), используя формат/битрейт/частоту, оставшиеся в
скрытых полях модалки одиночного экспорта. Нужно:

1. Показывать GUI-окно выбора перед экспортом (как у одиночного «Скачать»,
   по умолчанию без конвертации).
2. Добавить выбор: скачать отдельными файлами (текущее поведение) или
   склеить все выбранные фрагменты в один аудиофайл.
3. При склейке — расставлять в файле маркеры (главы) с названием по
   дате-времени начала каждого исходного фрагмента.

## Область действия

Затрагивает: `static/index.html`, `static/app.js`, `static/languages/*.json`,
`app/main.py`, `app/audio.py`. Новых зависимостей не требуется — `mutagen`
уже используется в `app/audio_probe.py`.

## UI: новая модалка «Экспорт всех фрагментов»

Отдельная модалка (`#export-all-modal`) с собственными ID полей
(`expall-*`), не переиспользует состояние модалки одиночного экспорта.
Открывается по клику на `#btn-export-all` вместо немедленного запуска
`exportAll()`.

Содержимое:

- **Режим** (радио, дефолт — «Скачать отдельными файлами»):
  - «Скачать отдельными файлами» — текущее поведение.
  - «Склеить фрагменты в один файл» — новый режим.
- **Формат / частота дискретизации / битрейт** — те же три select'а, что и
  в одиночной модалке (копия разметки/поведения `_updateExportFields`,
  выделенная в параметризуемый хелпер, чтобы не дублировать логику).
  Предзаполнение:
  - если все элементы лог-листа с одного канала → нативные
    формат/частота/битрейт этого канала (как в `openExportModal`);
  - если каналы разные → MP3 / 44100 Гц / 192 kbps.
- **Порядок склейки** (радио, видно только в режиме «Склеить», дефолт —
  «По времени начала фрагмента»):
  - «По времени начала фрагмента» — сортировка по `start` по возрастанию.
  - «Как в списке «Выбранные фрагменты»» — порядок `logItems` как есть.
  Сортировка выполняется на фронтенде перед отправкой запроса; бэкенд
  параметра порядка не принимает и обрабатывает `items` в переданной
  последовательности.
- **Предупреждение о маркерах** — короткая заметка, видна только когда
  режим = «Склеить» И формат = AAC: маркеры невозможны для AAC технически,
  файл будет склеен без меток.
- Строка прогресса (аналог `#export-progress` / `#play-loading`), кнопки
  «Экспортировать» / «Отмена».

## Данные и API

### Режим «Скачать отдельными файлами»

Без изменений на бэкенде. Фронтенд использует ту же логику, что и текущий
`exportAll()` / `doExportItem()` (цикл по `logItems`, `POST
/api/audio/export` на каждый, `_triggerDownload`), но с
форматом/битрейтом/частотой из новой модалки вместо скрытых полей
одиночной модалки.

### Режим «Склеить» — новый эндпоинт

```
POST /api/audio/export_merge
body: {
  items: [{channel_id, start, end}, ...],   # уже отсортированы фронтендом
  format: "mp3" | "wav" | "aac",
  bitrate: "192k" | null,
  sample_rate: 44100 | null
}
→ { filename, download_url }
```

`download_url` — существующий `/api/audio/download/{filename}` (путь уже
защищён проверкой `is_relative_to(EXPORT_DIR)`, изменений не требует).

### Бэкенд: `export_audio_merged()` в `app/audio.py`

1. Для каждого `item` — вызов существующего `export_audio()` во временный
   файл в общем `TemporaryDirectory`. Добавляется новый параметр
   `allow_copy_mode: bool = True` у `export_audio()`; при склейке
   передаётся `allow_copy_mode=False`, что отключает автоматическое
   copy-mode-переключение (`if not copy_mode and out_format ==
   native_ext...`). Склейка всегда транскодирует все фрагменты в
   единые параметры (формат/частота/битрейт из запроса) — это гарантирует
   совместимость при конкатенации фрагментов с разных каналов/форматов
   ценой небольшой потери качества в редком случае, когда все фрагменты и
   так уже в целевом формате.
2. Длительность каждого промежуточного файла измеряется через `mutagen`
   (`mutagen.mp3.MP3` / `mutagen.wave.WAVE` / `mutagen.aac.AAC` — по
   выбранному `format`), а не через `end - start`, чтобы избежать дрейфа
   меток из-за особенностей трима/паддинга при кодировании.
3. Файлы конкатенируются (`ffmpeg -f concat -safe 0 -c copy`) в финальный
   файл в `EXPORT_DIR`. Без затычек тишиной между фрагментами — это
   осознанная склейка отдельных выборок, а не непрерывный диапазон.
4. Маркеры встраиваются по формату (см. ниже).
5. Ошибка на любом шаге (стадирование фрагмента, транскодирование,
   финальный concat) прерывает всю склейку целиком — партиального файла не
   остаётся (временные файлы удаляются), ошибка транслируется через
   существующий `export_error` WS-broadcast и всплывает в модалке как текст
   в строке прогресса. Это отличается от режима «отдельно», где один
   неудачный фрагмент не останавливает остальные (текущее поведение
   `doExportItem`/`all_errors` сохраняется без изменений).

## Маркеры (главы) по формату

Проверено вручную на установленном ffmpeg (см. историю сессии):

- **MP3** — ffmpeg реально пишет и может прочитать читаемые ID3v2 CHAP-
  фреймы. Строится `;FFMETADATA1`-файл глав (`TIMEBASE=1/1000`,
  `START`/`END` в мс — кумулятивная длительность по факту, `title` —
  дата-время начала фрагмента), затем:
  ```
  ffmpeg -f concat -safe 0 -i segments.txt -i chapters.txt \
         -map_metadata 1 -map_chapters 1 -c copy \
         -id3v2_version 3 -write_id3v2 1 out.mp3
  ```
- **WAV** — ffmpeg честно логирует «Chapters» при муксировании, но
  WAV-мьюксер их не пишет физически (`ffprobe` после экспорта ничего не
  показывает). Вместо этого после обычной `-c copy`-склейки к результату
  вручную дописывается RIFF `cue ` чанк + `LIST`/`adtl`/`labl` подчанк —
  тот же байтовый формат, что у `Sound1.wav` (Sound Forge), который ffmpeg
  сам умеет читать обратно как главы. Позиции cue-точек — в сэмплах
  (`round(cumulative_seconds * sample_rate)`), заголовок `RIFF` size
  корректируется под новый размер файла. Реализуется отдельной чистой
  Python-функцией (без внешних зависимостей), не через ffmpeg.
- **AAC** — простая конкатенация без попытки встроить метаданные: сырой
  ADTS-поток не имеет контейнера для меток ни в каком виде.

### Addendum (после первого прохода реализации): MP3-маркеры для Sound Forge

Стандартные ID3v2 CHAP/CTOC-главы (см. выше) технически корректны и
читаются большинством плееров, но **Sound Forge их не показывает** — он
использует для MP3 собственный проприетарный формат маркеров, независимый
от ID3v2-глав. Обнаружено и реверс-инжинирено по образцу `Sound1.mp3`
(предоставлен для этой цели, аналогично `Sound1.wav`): маркеры хранятся в
ID3v2-фрейме `GEOB` с description `SfMarkers`, бинарный payload —
12-байтовый заголовок (константы `12`, `100`, затем количество маркеров) и
далее по одной записи на маркер: константа `28`, 8-байтовая позиция
little-endian в тиках по 100 нс (единицы Windows `REFERENCE_TIME` —
подтверждено сверкой с реальными позициями маркеров в образце), 12
зарезервированных нулевых байт, 4-байтовая длина текста (UTF-16LE, включая
2-байтовый нуль-терминатор), затем сам null-terminated UTF-16LE текст.

Реализовано как `_write_mp3_sf_markers()` в `app/audio.py` — постобработка
через `mutagen.id3` (уже зависимость проекта) поверх файла, который ffmpeg
уже вывел с ID3v2-главами: добавляется GEOB-фрейм `SfMarkers`, тег
пересохраняется. Оба механизма (ID3v2-главы и `GEOB:SfMarkers`) пишутся
одновременно и не конфликтуют — верифицировано, что пересохранение через
mutagen не портит уже записанные ffmpeg CHAP/CTOC-фреймы.

Название маркера — дата-время НАЧАЛА исходного фрагмента в том же формате,
что уже используется в лог-листе (`app.js:777`,
`ДД.ММ.ГГГГ ЧЧ:ММ:СС`).

## Имя склеенного файла

```
{Название канала} склейка с {YYYY-MM-DD HH-MM-SS}.{ext}
```

где `{Название канала}` — имя канала, если все элементы лог-листа с
одного канала, иначе литерал `Несколько каналов`. `{YYYY-MM-DD HH-MM-SS}`
— момент запуска экспорта. Санитизация имени — тем же способом, что уже
применяется для одиночного экспорта в `main.py:audio_export`
(`re.sub(r'[<>:"/\\|?*\x00-\x1f]', ' ', ...)`).

## i18n

Новые ключи в `static/languages/{ru,en,fr}.json` (секция `export`, по
образцу существующих `all_progress`/`all_done`/`all_errors`):

- `export.merge_mode_separate` / `export.merge_mode_merge` — подписи радио
  режима.
- `export.merge_order_label`, `export.merge_order_chrono`,
  `export.merge_order_list` — подписи выбора порядка.
- `export.merge_aac_warning` — предупреждение об отсутствии маркеров в AAC.
- `export.merge_progress` / `export.merge_done` / `export.merge_error` —
  статус склейки.
- `export.all_title` (или переиспользование `export.title` с параметром) —
  заголовок новой модалки.

## Вне области действия

- Заполнение тишиной между склеиваемыми фрагментами — не делается
  (осознанно, см. выше).
- Автоматических тестов в проекте нет; проверка — ручной прогон приложения
  (см. `CLAUDE.md`).
